# workflow-cookbook v1.3.0

## Summary

v1.3.0 packages the workflow modernization completed since v1.2.0. It adds
full-repository adoption, long-running context continuity, evidence-linked
HATE/QEG validation, and fail-closed CI coverage across supported platforms.

## Highlights

- `wfc-copy` installs and verifies the complete workflow contract in another repository.
- Adoption manifests preserve Git checkout hashes and detect text, binary, mode, and template-version drift.
- Long-running work keeps objectives, constraints, decisions, source hashes, and agent-taskstate snapshots available for reference.
- HATE test evidence feeds QEG eligibility and verdict records with pinned tool identities.
- Linux Python 3.11/3.12 and Windows adoption CI run required suites without hidden skips.
- Version consistency validation accepts one fully aligned package release candidate before its Git tag is published.

## Compatibility

- Python 3.11 and 3.12 are supported.
- Existing adoption manifest v1 records remain verifiable; new copies use manifest v2.
- Existing public CLI entry points remain available.

## Validation

- The v1.3.0 wheel and source archive are built from the versioned source metadata.
- Package metadata, README badge, changelog, release note, and lockfile are checked for version alignment.
- The release-candidate checker tests tagged, pending, stale, and unrelated untagged release states.

## Known constraints

- The package and release note may land before tag publication; the checker reports that state as a pending-tag warning.
- QEG's pinned lockfile currently reports the existing transitive `fast-uri` npm audit warning.
- Feature and regression tests do not establish a model-performance or long-horizon drift-rate improvement.
